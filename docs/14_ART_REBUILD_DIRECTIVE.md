# 14 — MANDATORY: complete environmental artwork replacement

## Client feedback and overriding decision
ALL prior environment and prop artwork is REJECTED for lack of depth, richness, shadows and gradients. This directive supersedes every older document that calls the 60 SVGs production-ready. The 60-layer **scene architecture** is retained as a target, not the old art. Icons and character are approved exceptions. Never copy the rejected environment into the runtime app.

## Premium visual target
A lush, highly crafted 2.5D layered **paper-diorama storybook**: joyful luminous palette, hand-cut irregular edges, believable cardstock thickness, soft directional light, subtle paper fibers, ambient occlusion at overlaps, nuanced gradients, edge bounce-light, atmospheric perspective, coherent shadows, natural forms, tiny delightful details. Avoid plasticky 3D, glossy glass, neon, flat circles/polygons, thick outlines, stock illustration, or photorealistic landscapes. Paper material must remain evident. Reference approved app icon for palette/whimsy, not as a flattened scene to slice.

## Creation method
Use professional image/design generation for visual masters, then separate layered components (PSD/SVG/transparent lossless WebP or PNG) with consistent perspective. Reconstruct occluded areas; don't merely crop one flattened picture into layers. Each layer must have transparent background, clean antialiased edge, safe overlap margins and named anchor/registration points. SVG is acceptable ONLY if its actual aesthetic passes art QA; high-fidelity transparent raster layers are preferable to cheap SVG stand-ins. Preserve source/editable masters when possible. Do not claim an image is layered if it is a flat bitmap.

## Required first checkpoint
1. One detailed DAY master and one NIGHT master using identical world layout and scene anchors, 390x~620 logical viewport with 390x844 screenshot composition.
2. Contact sheet showing isolated sky, far clouds, sun/moon, horizon, hills, village, trees, river, flowers, fauna, foreground occluders, particles and UI-safe zones.
3. Export at 2x/3x where raster; consistent color profile; provide dimensions, transparency, source and license.
4. Mobile screenshots at 320, 375, 390, 430px widths; check no seams/white gaps/scale mismatch.
5. User explicitly approves art BEFORE mass-producing remaining assets.

## Light and depth
Define key light upper-left for day, warm dusk side light, moon/cottage light for night; contact shadows follow one direction. 4–7 perceptible depth planes, not 60 independently moving foreground objects. Use multi-stop subtle color gradients within cardstock, soft shadow layers under edges, rim highlights, controlled grain. Background is light, not black-heavy.

## Character and icons
Preserve existing approved icon pack and paper character. Character animations need true expression-specific poses; if current GIF/WebP are simple bobbing placeholders, list them as prototypes. Character is optional cameo, not hero. The old Rive original is not a runtime dependency.

## Final QA gate
At 100% scale, screenshot must look like a premium illustrated storybook, not flat vector clipart. Check layering and occlusion, visual balance with 3 habit cards, typography readability, animation frame stability, and runtime performance. If artistic standard cannot be met, request a designer/image generator and DO NOT proceed with fake completion.
